# アイディアワークショップ支援ツール

デザイン思考ワークショップの「気づき → カード選択 → 議論・可視化 → 投票」をチームで進める、日本語のWebアプリです。仕様 v0.5（Notion本文・マップ・カード選択・議論・投票集計の同期）。

## すぐに体験する

Node.js 24以上とpnpmが必要です。実装はサーバーを含むため、GitHub Pagesだけでは稼働しません。

```sh
pnpm install --frozen-lockfile
node server/demo.js
```

[http://localhost:4317](http://localhost:4317) を開き、5秒のオープニング後に「本人確認してログイン」を押し、「管理者」「編集者」「閲覧者」を選びます。体験データは `demo-data/`、通常のデータは `data/` に分離します。体験モードはループバック専用で、本番認証・Notion・AI送信を使いません。初期画像は提供ファイルを無加工で収録しています。

1. ①の「＋ トピック」やEnter／Insertで追加。ダブルクリックで直接編集、Enterで同階層、Insertで子を追加。ドラッグで枝の接続・切離し、＋／−で展開・折り畳み。縮尺の右の全体表示アイコンで画面内へ収められます。
2. ②で管理者がタイマーを開始し、＋／−で投票。初期10票、同じ案に複数投票できます。
3. ③でデッキ横の得票済みカードをゴールドの台座へドラッグ、または＋で追加。議論を開始し、記録とWHAT／WHO／HOWを保存します。終了・レビュー・再開を繰り返せます。
4. AIが認可・接続済みになると、レビューして画像を適用し、④で全チームの画像へ投票できます。
5. 管理者設定でWSを「完了（変更不可）」にすると、チーム別Markdownと生成済みPNGをダウンロードできます。

## 通常起動

`.env.example` を `.env` にコピーし、サーバー側で設定します。秘密・メール・稼働データはコミットしないでください。

```sh
node --env-file-if-exists=.env server/index.js
```

まず `BOOTSTRAP_ADMIN_EMAIL` とSMTPを設定します。登録済みメール＋メールOTPで初回ログインし、右上のアカウントボタンからパスワード、パスキーボタンからパスキーを登録できます。設定済みパスワードがある通常ログインはパスワード＋OTP、参加QR経由は登録メール＋OTPです。次回はパスキーでもログインできます。パスキーはサーバーでchallenge・Origin・RP ID・署名・ユーザー検証を検証します。

Notionトークンがなくても、SMTPと初期管理者があればサーバー単体でWSと参加者を管理できます。SMTP未設定では通常ログインは停止します。認証成功を装う代替経路はありません。Notionの「OTP認証結果」は認証判定に使いません。

## 構成と共同編集

Node.js標準HTTP＋SQLite（WAL、`BEGIN IMMEDIATE`）＋フレームワーク不要のフロントエンドです。操作はサーバーに保存し、約3秒ごとの更新で共有します。投票はトランザクションと操作IDで予算・同時操作・再送を制御。マップ／議論等はrevisionで競合を拒否します。入力中の画面は新着通知を表示して下書きをメモリーに保持します。競合時には最新共有データを確認し、必要な内容を再適用してください。CRDTによる同一テキストの同時編集ではありません。

NotionはWS名・状態・終了日・参加者・権限・グループに加え、①のトピック階層のマスタです。起動時に読み込み、マップの編集を即時に書き戻します。②③④も班別に記録し、デッキ・議論・合計票を復元します。SQLiteには作業状態・個人票・セッション・未同期操作を保持します。Notionと同時に変わったマスタは上書きせず競合にし、管理者が採用先を選びます。同期中の書込みは短時間409で止め、SQLite上の共同編集を上書きしません。Notion管理WSは権限再確認が60秒以上古い場合、または同期失敗・競合中の場合、参加者アクセスを停止します。設定済みの初期管理者は復旧作業を続けられます。

## 検証

```sh
node scripts/check.js
node --test --test-concurrency=1
```

テストは一時SQLiteと明示的なテスト用送信アダプターを使用し、本番Notionを変更しません。HTTPテストはローカルポートへの接続が必要です。実行結果と制限は [検証記録](docs/VALIDATION.md) を参照してください。

## 運用

外部公開にはHTTPSと `SECURE_COOKIE=true`、正確な `APP_ORIGIN`／`RP_ID` が必要です。HTTPS終端の内側で単一Nodeプロセスとして運用してください。SQLiteは同一ホストのローカルディスクに保存し、複数レプリカや共有ネットワークボリュームで同時稼働させないでください。データ／監査ログには参加者・議論・画像が入ります。アクセス可能な運用者を制限し、保存期間を定めてください。バックアップはサーバーを停止してデータディレクトリ全体をコピーするか、SQLiteのバックアップ機能を使います。WAL稼働中にDBファイルだけをコピーしないでください。

初期管理者のメール変更・認証の復旧はサーバー運用者が行います。`.env` の値を変えて既存アカウントのパスワードを上書きする動作はありません。パスワードの自己変更は現在のパスワードが必要で、変更時は他端末のセッションを失効します。初回設定は直近15分のログインを要求します。
