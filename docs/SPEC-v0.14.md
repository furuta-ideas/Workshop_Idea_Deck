# v0.14 Notionの「ワークショップの履歴」形式

v0.13のDB形式（② カード選択などの4つのDB）と、v0.12以前の①〜④見出し＋JSON形式は廃止しました。Notionには、人が読みやすいトグル形式の履歴だけを保存します。

## 保存するタイミング

| 操作 | Notionへの記録 |
| --- | --- |
| ③の「記録を保存」 | そのチームの履歴を1件追加 |
| ③で生成した画像（企画提案シート）を「確認して適用」 | 画像付きの履歴を1件追加 |
| マップ編集・投票・設定画面の保存など | Notionへは書かない（アプリのサーバーにだけ保存） |

記録はバックグラウンドで送ります。通信断・混雑・Notion障害の場合は30秒→1分→…最大10分の間隔で自動再送します。

## ページの構成

```
## ワークショップの履歴
▸ yyyymmdd_hhmmss_ワークショップ名（テンプレート）   ← 人が置く見本。アプリは読まない
▸ 20261108_221400_ビザスクセミナー＿A班              ← 新しい履歴はテンプレートの直下（一番上）に追加
    ▸ 求められる世界        ▸ マップの中心テーマ
    ▸ マインドマップ        トピックの階層（入れ子のトグル、色＝グループ）
    ▸ ペーパープロトタイプ  生成した画像
    ▸ 模擬プレスリリース    本文（段落）
    ▸ アイデアの輪郭        一言で言うと：… ／ Who：… ／ What：… ／ How：… ／ 特長1〜3：… ／ キーワード：…
    ▸ 議論メモ              議論の記録（段落）
    ▸ 設定情報
        ▸ AIファシリテータ（プロンプト）
        ▸ ペーパープロトタイプ（プロンプト）
        ▸ 模擬プレスリリース（プロンプト）
        ▸ 投票結果          JSON（下記）
## アプリの設定
  参加者一覧（DB）
```

- 履歴のタイトルは `yyyymmdd_hhmmss_WS名＿チーム名`（日本時間）です。末尾がチーム名と一致するものだけを、そのチームの履歴として読みます。「（テンプレート）」「（データ記入例）」のように末尾に別の文字があるトグルは読みません。
- 「ワークショップの履歴」見出しがないページでは、最初の保存時にページ先頭へ作ります。
- 「アイデアの輪郭」「議論メモ」は、③の入力欄を漏れなく残すためにアプリが追加したセクションです。

### 投票結果のJSON

```javascript
{
  "cards": [
    { "id": "アプリのカードID", "text": "トピック #VOTES:3", "notionBlockId": "マインドマップ内のブロックID" }
  ],
  "deck": [ { "id": "アプリのカードID", "notionBlockId": "…" } ],
  "ideaVotes": 0
}
```

`cards` は②で1票以上のカード、`deck` は③のデッキ（最大5枚）、`ideaVotes` は④でそのチームが得た票数です。票数は `#VOTES:` の後の数字を読みます。

## Notionがマスター

- アプリは利用中、約1分ごとに各チームの**最新の履歴**を読みます。前回アプリが書いた／読んだ内容から変わっていれば、そのチームをNotionの内容で復元します（マップ・中心テーマ・本文・輪郭・議論メモ・票・デッキ・画像・プロンプト）。
- サーバーのデータが空のとき（初期化・移設）も、最新の履歴から復元します。
- 管理者設定の「Notionから再読込み」で、変更の有無にかかわらず最新の履歴を読み直します。
- 履歴を読めない場合（JSONの破損など）は「Notionの履歴を読み込めません」と表示します。その間も新しい保存の送信は続けます。

注意：Notionで最新の履歴を直すと、その班の「最後の保存以降の、まだ保存していないアプリ上の編集」はNotionの内容で置き換わります。Notionで直すのは、ワークショップを使っていない時間がおすすめです。

## AI設定

プロンプト3種は、保存のたびに各履歴の「設定情報」に書きます。Notionで最新の履歴のプロンプトを直すと、次の読込みでアプリのAI設定に反映します（全WS共通の設定です）。

## v0.14.1 修正

- **①マップの振動**：拡大率の表示（例：99%⇔100%）の文字幅でツールバーの折り返しが変わり、マップの高さ→「画面に合わせる」の拡大率→表示…と再計算が無限に続いていました。拡大率表示とタイマーを固定幅の数字にし、スクロールバー分の幅を常に確保、さらに直前と同じ大きさへの往復を検知して再計算を止めるようにしました。
- **③④の横はみ出し**：区切りのない長い文字列や幅の大きい要素があっても画面幅を超えないよう、各領域の最小幅を0にし、長い文字列は折り返すようにしました。
- **③の文字サイズ**：ディスカッションの記録・アイデアの輪郭・３つの特長などを既定で115%に拡大。管理者設定の「表示の設定」で 標準100%／大きい115%／さらに大きい130%／特大150% を選べます（WSごと・参加者全員に反映）。
- **③の＋・録音が押せない**：Notionの参加者DBの「グループ」が複数選択（multi_select）型だと参加者の同期が止まり、誰もどの班にも属さない＝全班が閲覧のみになっていました。「グループ」は単一選択・複数選択のどちらでも読み込み（複数あるときは最初の班）、書き戻しもDBの型に合わせます。

## v0.14.2 画像生成の修正

- **生成結果が捨てられる問題**：画像生成（1〜3分）の間に、WS内の誰かが1回でも編集すると「AI処理中に更新されました」で結果を破棄し、確認中に編集があると適用も拒否していました（Genspark側では生成済み＝クレジット消費済み）。結果はチーム単位のデータなので、WS全体の更新番号では拒否しないようにしました。
- **GensparkのWAF**：Gensparkは `/api/tool_cli/` への呼び出しに、短時間有効な通行証（`X-Genspark-Token-Pass`、公式CLIと同じ方式）を求めるようになりました。通行証を取得して付けます（取得できない場合は従来どおり送信）。
- **画像の受け取り**：画像URLの転送（リダイレクト）を、許可したGensparkのドメイン内で最大3回までたどります。PNG以外（JPEG/WebP）が返った場合は、確認画面でブラウザーがPNGに変換してから適用します。
- **画像モデルの指定**：管理者設定に「画像モデル」欄を追加しました（既定 `gpt-image-2.5`）。「Gensparkで使えるか確認」で、お使いのGensparkキーで使えるモデルを照合します。使えないモデルを指定した場合は、Gensparkに送る前に使えるモデルを示して止めます。文章モデル欄に `gpt-image-…` を書いた場合は、画像モデルとして扱います。
- **エラー表示**：Gensparkのエラー内容（HTTP状態と理由）を画面に出すようにしました。

## v0.14.3 Gensparkの残クレジット表示と消費量の実測

- 管理者には、右上のメールアドレスの下に「Genspark残り ○○ クレジット」を表示します。Gensparkの `GET /api/tool_cli/me` の応答から残高を読みます（項目名が非公開のため「credit」を含む数値項目を探します）。問い合わせは最大5分に1回で、結果はメモリーだけに保持します（Cloudflareへの書込みなし）。
- AI処理（音声認識・模擬プレスリリース・画像生成など）の前後で残高を取り、その差を処理ごとの消費量として記録します。同時に別のAI処理が動いた回は記録しません。管理者設定の「Gensparkのクレジット消費（実測）」に回数・平均・直近を表示します。
- （v0.14.4）残クレジットを横棒の残量バーでも表示します。満タンの基準は、Gensparkが月の枠（credit…total/limit/monthly など）を返していればその値、返していなければ今月見えた最大の残高です。残量50%以上は緑、20〜50%は黄、20%未満は赤です。Gensparkに未接続のときは表示しません。

## v0.15.0 ③デッキのリフレッシュと履歴

- ③「アイデアのデッキ」の見出しにリフレッシュボタン（↻）を置く。押すと確認の後、今のデッキ・ディスカッションの記録・アイデアの輪郭・３つの特長・模擬プレスリリース・企画提案シートを「デッキ＃n」として保存し、空のデッキにする（送信前の入力も保存に含める）。
- 保存したデッキは「デッキ＃1」「デッキ＃2」…のアイコンで並び、押すとそのデッキへ戻る。戻る前の編集中デッキも、カードか記録があれば自動で保存する。空のデッキは保存しない。
- 企画提案シート（画像）を適用すると、そのデッキに保存する。④はデッキごとに別の項目として表示し（「チーム名 デッキ＃n」）、投票もデッキごとに数える。デッキ導入前の画像はチーム単位の項目として残す。
- Notionの「アイディア投票数」はチームのデッキ合計を送る。Notion側で数を変えた場合だけ、差分をチームの票として取り込む。

## v0.16.0 ログイン・キャラクター・Genspark診断・②の記録・Notion保存

- **24時間ログイン**：メールの認証コード（OTP）でログインすると、そのブラウザーでは同じメールアドレスなら24時間はOTPなしでログインできる（HttpOnlyの通行証クッキー `wid_trust`、`/api/auth` のみに送信）。24時間はOTP入力時刻から数え、過ぎたら再びOTP。別のメールアドレス・別のブラウザーは常にOTP。セッションも最長24時間。
- **キャラクター**：AIアドバイスのキャラクターは1体だけ表示。管理者設定「表示の設定」でカシー（男の子）/リーフィー（女の子）をワークショップごとに選ぶ（既定はカシー）。
- **Genspark**：保存済みのGensparkキーがあれば、使用サービスが未設定のEnterpriseになっていてもGensparkを使う（全AIボタンが無効になる不具合の修正）。入口（WAF）の403は通行証を取り直して1回だけ再送。通信エラーは原因を表示し、「最後のAIエラー」として管理者設定に残す。管理者設定に「Genspark接続テスト」（WAF通行証→アカウント確認→ツール一覧の各段階のHTTP状態）を追加。
- **②の記録**：②に「ディスカッションの記録」（録音開始・記録を保存）を追加。③と同じ記録に保存する。
- **Notion保存**：
  - 「記録を保存」を押さなくても、議論の変更（入力・AI整理・模擬プレスリリース・文字起こし・デッキの選択）を1分ほど待ってチームごとに1件の履歴にまとめて書く。
  - 新しいデッキにする／別のデッキに戻すときは、離れるデッキを未送信の入力ごと履歴に残す。
  - 設定（AIプロンプト・文章／画像モデル・ファシリテータmd・文字サイズ・キャラクター・投票設定）を保存すると、ページの「アプリの設定」見出しの直下に「設定情報（アプリの最新設定）」を最新の内容で置き換えて書く。

## v0.17.0 ③の画面構成と低コストのAIモデル

- ③から「ディスカッションの記録」（録音・議論メモ）を外す（記録は②で行う。「✧ 議論を整理」は②の記録を使って輪郭を埋める）。
- 「アイデアの輪郭」を左右2列に配置：左に一言で言うと／Who／What／How、右に３つの特長（折り返して全文が見える入力欄。改行は空白に置き換えて１行で保存）。幅900px以下は1列。
- その下に「模擬プレスリリースの生成」と「ペーパープロトタイプの生成」を左右に並べ、それぞれの下に生成した原稿・画像を表示する。
- 既定のAIモデル：
  - 文章：管理者が指定しない場合、Gensparkのモデル一覧から無料（価格0）→最安→軽量（haiku/flash/mini/lite/nano）→Gensparkの既定の順で自動選択。
  - 画像：`gpt-image-2`（ChatGPT Image 2.xで最も手頃。Plus/Proの標準品質はクレジット消費なし、無料プランでも1Kで約5クレジット）。標準設定（1K・上位tierなし）で生成し、2Kと`flare`は2.5以降を選んだときだけ使う。
  - 既存の保存設定は一度だけこの既定に移行し、その後に管理者が選んだモデルは保持する。
