# レビューと実接続への引継ぎ

実装対象は `furuta-ideas/Workshop_Idea_Deck` だけです。取得時は空リポジトリでした。別の参考リポジトリを変更・pushしていません。

## 読む順番

1. `docs/SPEC-v0.3.md`：確定仕様と合理的な仮定。
2. `server/domain.js`：権限・状態・期限・投票・デッキ・議論制約。
3. `server/auth.js`：OTP、パスワード、WebAuthn、セッション。
4. `server/notion.js`：子DB発見／生成・マスタ同期・競合・成果保存。
5. `server/ai.js`：認可ゲート、サービス／モデル、送信制約と監査。
6. `public/`：画面と手動入力、適用前レビュー。
7. `test/` と `docs/VALIDATION.md`：独立した検証と残る限界。

## 接続担当者が用意するもの

| 接続             | 必要なもの                                                                                |
| ---------------- | ----------------------------------------------------------------------------------------- |
| メール認証       | SMTPホスト／ポート／TLS／送信者／資格情報、初期管理者メール                               |
| WebAuthn・参加QR | 配置先のHTTPS URL、RP ID、APP_ORIGIN、Secure Cookie設定                                   |
| Notion           | 長期API資格情報、WS一覧data_source ID、親／子DBと成果作成先への共有権限、標準テンプレート |
| AI               | GSK/API利用可否、正式仕様、6機能の社内認可、正式Gateway接続先・キー・認可根拠             |
| 画像生成         | 後日指定する生成プロンプト、必要に応じ承認モデル名。既定モデルは未指定のまま              |

## 実接続の受入確認

- 専用のNotion検証DBとテスト用メールを利用する。本番参加者や実際のOTP履歴を自動テストに投入しない。
- 実メール配信 → OTPログイン → パスワード設定 → 次回パスワード＋OTP → パスキー登録／次回ログインを実端末で確認する。
- 管理者／編集者／閲覧者の3端末でチーム共有、競合通知、同時投票、完了・破棄・期限、ログイン後の権限変更を確認する。
- Notion側／アプリ側のWS追加・更新・削除、子DB生成、グループ割当、同期停止と回復を確認する。
- 承認Gatewayの監査とネットワークログで6機能が許可された送信先・下流モデルだけを使うことを確認する。失敗しても別会社への通信がないことを確認する。
- マイク許可と実音声、途中整理、レビュー後の適用、16:9画像生成、④の投票、PNG／Markdown／Notion成果保存を確認する。
- PC・タブレット・狭い画面・キーボード操作を実ブラウザーで確認する。

## 技術上の限界

初期版は単一サーバー＋SQLite、小〜中規模WS向けです。共有は3秒ポーリングで、CRDTやオフライン編集ではありません。下書きはブラウザーのメモリーに保持され、リロードすると失われます。操作が競合した場合は、共有データを確認して再保存します。

Notionの比較更新は原子的でなく、同期による権限反映には最大約30秒かかります。権限再確認ができなければ60秒を上限として停止します。Notion管理WSの可用性より、権限の不確かな状態でのアクセス拒否を優先します。

Gmailの実SMTP認証・OTP送信とGmail受信箱への到着を確認済みです。会社メールは送信サーバーでの受理まで確認し、受信箱への到着は未確認です。受信したOTPでの実ログイン・実パスキー・本番Notion・実AI・録音・実画像生成の受入試験は未実施です。ネイティブブラウザー起動の承認タイムアウトにより、目視QAも未実施です。DOMテストは目視・実端末試験の代替とはみなしません。
