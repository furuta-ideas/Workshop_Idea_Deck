最初のSecret登録は自動承認レビューに拒否されたため停止し、利用者が専用WorkerへのGmail/Notion秘密設定とワークショップデータの移行を明示許可した後に実施しました。Gmail SMTP認証とNotion実読取りが公開Workerから成功しました。公開側ではNode互換の呼出し元とリダイレクト指定を調整し、転送先へ資格情報を送らない方式を保持しました。

ローカルの通常アプリを停止してSQLiteの整合バックアップを保存し、62項目と班別の議論・デッキ・票・利用者設定・AI用mdを専用の認証保護された永続ストレージへ移しました。移行前後の内容ハッシュとmdハッシュが一致しています。移行時のSecretを削除し、移行APIが404、未認証のWS一覧が401、通常モードとOTP設定有効のヘルスチェックが200になることを確認しました。ログイン画面も公開URLで表示できました。

GitHub Pagesの公開元をworkflowへ変更し、入口のHTMLと転送用JSだけを公開するワークフローを追加しました。公開側でのOTPメール受信からログインまでの最終確認は利用者が行います。今回の公開確認では追加のOTPメール送信・テスト用トピックの実追加は行っていません。

アラームについては、複数ブラウザーから照会が続いても実行期限が後ろへずれ続けないことを追加テストで確認しました。

GitHub Pagesの公開ジョブが成功しました。CI側の初回インストールはpnpm 11でesbuild/workerdのビルド許可が未指定のため停止したので、この2つの公式依存だけをallowBuildsへ登録しました。同じ固定ロックのインストールと全81件のテストがローカルで成功しています。

GitHub上のCIも81件で成功しました。追加した大容量JSONの保存テストを含めてローカルでは82件が成功しています。SQLiteの行サイズ上限に合わせて本文を512KBずつのBLOBに分割し、2,800,713バイトの架空Unicode文書を実ローカルWorkerへ保存・復元してハッシュが一致しました。更新・削除・期限切れ削除時の分割データの整理と、トランザクションの整合性も確認しています。GitHub Pagesから実ブラウザーで専用アプリへ移動し、ログイン入口と認証フォームが表示されることを確認しました。
