# v0.13 Cloudflare書込み削減・Notion DB化・AIアシスタント強化

> **v0.14で変更：** この版の「②③④のNotion DB化」は廃止し、[v0.14の履歴トグル形式](SPEC-v0.14.md)に置き換えました。Cloudflare書込み削減・自動再送・AIアシスタントの内容は有効です。

## 1. Cloudflare Durable Objects の書込み削減

無料枠は1日あたり `rows_written` 100,000件です。v0.12までは次の理由で、利用者がいない時間も上限近くまで書き込んでいました。

| 原因                                                                     | v0.13の対策                                                                       |
| ------------------------------------------------------------------------ | --------------------------------------------------------------------------------- |
| 30秒ごとのNotionポーリングが24時間動き続ける（約2,900回/日）             | 最後のアクセスから10分間だけポーリング。無人の時間はアラームを止める              |
| ポーリングごとに全WS・全参加者・同期状態を書き直す                       | `Store.put` は内容が同じなら書き込まない                                          |
| `checkedAt`・`dueAt`・同期時刻など毎回変わる時刻が「変更あり」になる     | 揮発フィールドとしてメモリーだけに保持（再起動時は0＝安全側）                     |
| Notion本文キャッシュに署名付き画像URLが含まれ、60秒ごとに全体を再保存    | キャッシュを差分計算に必要な項目だけに圧縮                                        |
| マップ編集のたびに画像（数MBのbase64）を含むWS全体を分割保存             | チーム画像はハッシュ単位で1回だけ保存し、WS本体には参照だけを置く                 |
| AIアシスタントの15秒タイマーごとにレート制限・状態を書込み               | AI助言のレート制限と思考中フラグはメモリーで管理                                  |

テスト `書込み予算` で、変化のない定期同期20回の書込みが0件であることを確認します。

## 2. Notion同期の信頼性

- 一時的な失敗（通信断・429・Notionの5xx）は30秒→1分→2分…最大10分の間隔で**自動再送**します。v0.12は1回の失敗で送信が止まり、手動の「再試行」まで保存されませんでした。
- 競合・不正な内容など人の判断が必要な失敗は、従来どおり自動再送しません。
- 送信は「操作が10秒止まったら」。ただし連続で操作していても**最初の変更から最長2分**で送ります。
- 設定画面の保存ボタン（WS設定・AI設定・ファシリテータmd）は押した時点で送信します。

## 3. ②③④と設定のNotion DB化

①はこれまでどおりチーム別トグルの階層です。②③④と設定画面の内容は、JSONのコードブロックをやめ、WSページ直下の4つのインラインDBに保存します。

| DB名            | 1行の単位            | 主な列                                                                                                     |
| --------------- | -------------------- | ---------------------------------------------------------------------------------------------------------- |
| ② カード選択    | 票またはデッキのカード | カード／チーム／得票／デッキ／デッキ順／カードID                                                           |
| ③ アイデア企画  | チームの作業中の案・保存した企画 | 一言で言うと／チーム／状態／Who／What／How／特長1〜3／キーワード／ポイント／模擬プレスリリース／議論メモ／使用カード／企画シート（画像）／更新日時 |
| ④ 投票結果      | チーム               | チーム／得票／一言で言うと／What                                                                           |
| ⚙ アプリの設定  | 設定項目             | 項目／値／区分（ワークショップ・チーム・AI）／キー                                                         |

- 「〇〇ID」「キー」の列はアプリが行を対応付けるための列です。ビューで非表示にして構いません。値は変更しないでください。
- Notionでセルを編集すると、次の読込み（最長約1分）でアプリへ反映されます。アプリ側に未送信の変更がある間は読込みを待ちます。
- 列を消した場合は次回の保存で列を追加し直します。DBそのものを消した場合は作り直します。
- DBはAPIの制約でページ末尾に作成されます。各見出しの下へドラッグで移動して構いません（位置は問いません。タイトルで探します）。
- テンプレート「ワークショップテンプレート」にも同じタイトルの4つのDBを置くと、新しいWSでは最初から見出しの下に並びます。

### 旧形式からの移行

v0.12のJSON記録があるページは、初回の読込みでJSONの内容を取り込み、次の保存でDBへ書き出した後、②③④のJSONトグルをゴミ箱へ移します（Notionのゴミ箱から復元可能）。

### 設定の往復

AI設定（模擬プレスリリース用・企画提案シート用プロンプト、モデル、ファシリテータmd）は全WSで共通です。保存ボタンで接続中の全WSの「⚙ アプリの設定」に書き、Notionで編集された値は次の読込みでアプリへ反映します。

## 4. AIアシスタント（Genspark経由のみ）

会話ダイアログに、タブごとの「よく使う相談」チップを追加しました。押すとすぐ送信し、画面に表示中のトピック・カード・入力欄の内容（未保存を含む）を送信時点で読み直して添えます。

| タブ | チップ                                                   |
| ---- | -------------------------------------------------------- |
| ①    | グループ分けして／足りない視点は？／選んだ枝を深掘り     |
| ②    | デッキ候補を選んで／票の傾向は？                         |
| ③    | 一言で言うと×3案／Who/What/How整理／３つの特長の案／弱点と改善案 |
| ④    | 案を比較して                                             |

- AIが示した候補（一言で言うと・Who/What/How・特長・トピック）は回答の下に一覧表示し、「③に反映」「マップに追加」で1クリック採用できます。
- グループ分けの回答は「マップの色に適用」で反映でき、Ctrl+Zで戻せます。
- 候補は欄ごとの文字数・形式をサーバーで検証し、メールアドレスを含むものは捨てます。
