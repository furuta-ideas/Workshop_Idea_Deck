# v0.6.1 操作停止後10秒のNotion同期

同期中の操作制限は[v0.8](SPEC-v0.8.md)で廃止しました。10秒の待機は継続し、送信処理を作業状態から分離しています。

①のマップ更新ではNotion APIの応答を待たず、変更をサーバーのSQLiteへ先に保存して画面へ返します。追加・直接編集・中心トピック編集・移動・切離し・削除・分類の取り消し、承認したAI分類とマップ用文字起こしに適用します。

- 最後の操作から10秒以上経過したかをサーバーが1秒ごとに確認し、未同期の最新内容をまとめて送信します。既存のNotion処理が実行中の場合は、その完了後に送信します。
- 続けて操作すると10秒の待機をやり直します。マップ上の文字入力・キー操作・ドラッグ等も、最大毎秒1回の活動通知で待機を延長します。画面が開いたままという理由だけでは延期しません。
- サーバーへ届いた変更は待機中も永続化されます。ブラウザーを閉じても送信予約は残り、サーバー再起動後も継続します。未確定の入力欄の文字は保存操作が必要です。
- 同期待ち中は追加編集を許可し、「サーバーに保存済み・操作停止10秒後にNotionへ同期」と表示します。待機中の②③④等の操作も同じ送信にまとめ、マップを途中で即時送信しません。
- 送信中は従来の競合防止ロックを使います。Notion送信そのものの高速化や、送信中の同時保存を行う変更ではありません。入力途中の下書きは画面に保持します。
- Notionからの定期読取りは継続しますが、未同期のローカルマップを上書きしません。送信前にNotion原文を再確認し、外部更新があれば両方を保持して競合を表示します。
- 送信失敗は自動的に無限再送せず、変更を残して再試行ボタンを表示します。手動の再試行は10秒を待たずに実行できます。管理者がNotionを採用して再読込みする場合は、未同期内容を別途バックアップします。
- 作成して送信前に削除したトピックは、Notionへ追加しません。重複した操作IDによる再送では待機時間を無駄に延ばしません。

②③④で新しく始める操作は従来どおりです。すでにマップの送信待ちがある場合だけ、同じ待機中の作業へまとめます。WSの状態・権限・参加者の同期方式は変えません。

運用確認用の`scripts/check-notion-content.js --roundtrip`は、明示的に同期を完了して読返しを検証するコマンドです。通常画面の待機方式とは区別します。
