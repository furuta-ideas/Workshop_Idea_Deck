# v0.6 ①をチーム別の通常トグルへ統一

①の階層形式を次の構造に統一します。ステップを区切る通常見出しは残し、その配下はチーム名もトピックも通常のトグルにします。トグル見出し2・3・4は使いません。

```text
① もやもやの言語化（N1）
  ▸ チーム：A班
      ▸ メイントピック
          ▸ 子トピック
              ▸ 孫トピック
                  ▸ 以降も同じ通常トグル
      ▸ 別のメイントピック
  ▸ チーム：B班
  ▸ チーム：C班
② 言語化の絞込み（カードの選択）
  ▸ チーム：A班
      要約と復元用JSON（従来どおり）
```

チーム名のトグルは班の区切りとして扱い、マップのトピックにはしません。空の班にも専用のトグルを作ります。親子関係はトグルの入れ子だけで決まり、深さによるブロック種別の切替はありません。

## 旧形式からの移行

起動時の読取りは旧見出し・箇条書きにも対応します。旧形式を保存するときは、本文・色・論理ID・親子関係を保持し、専用のチームトグル内へ通常トグルとして作成します。Notionは既存ブロックを別の親へ直接移動できないため、作成を確認してから旧ブロックをTrashへ移します。元のブロックIDは変わりますが、カードの論理ID、選択デッキ、合計票を保持します。

移行中は旧ブロックと新ブロックが一時的に共存することがあります。処理履歴から同じ作成結果を回収し、途中で通信が切れても重複作成せず再開します。通常の読取りは重複した論理IDを引き続き拒否します。画像等を含む未対応の枝は自動移行を停止し、元の内容を保護します。

既存の全班を一括移行する運用者用コマンドは、アプリを停止して整合バックアップを保存した後に実行します。

```sh
node --env-file=.env scripts/check-notion-content.js --normalize --page=対象NotionページID
```

この処理は実Notionを書き換えます。対象ページの明示を必須にし、移行後にNotionを読み返して本文・階層・論理ID・色・デッキと全トグル構成を確認します。新規のテストトピックは作りません。

## 同期の扱い

Notionをマスターとして起動時・定期同期で読み込みます。マップの変更はサーバーへ先に保存し、[v0.6.1の10秒待機同期](SPEC-v0.6.1.md)で同じトグルへまとめて反映します。競合時は入力を保持し、Notionの更新を古い内容で上書きしません。他班は閲覧専用です。②③④の保存形式と投票の扱いは[v0.5の同期仕様](SPEC-v0.5.md)を引き継ぎます。
