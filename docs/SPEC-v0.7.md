# v0.7 GitHub PagesとCloudflareでの公開

入口は`https://furuta-ideas.github.io/Workshop_Idea_Deck/`です。認証・画面・APIを同じオリジンで動かすため、`https://workshop-idea-deck.furuta-ideas.workers.dev/`へ移動します。ワークショップ招待のクエリーは移動後も引き継ぎます。

専用Workerは既存のCloudflareアカウントへ作成し、Tour PlayBookのコード・Worker・データは変更しません。新しい契約や有料プランへの変更はしていません。

## 実行と保存

- 従来のHTTP・認証・権限・マップ処理を、CloudflareのNode HTTP互換機能で実行します。
- アプリのデータは専用のSQLite-backed Durable Objectへ保存します。複数のブラウザーからの投票・編集は、同じオブジェクトの同期SQLとトランザクションで処理します。
- 管理者が編集するAI用mdも同じ永続ストレージへ保存します。
- 大きい画像等を含むJSONは512KBのBLOBへ分割してSQLiteの行サイズ上限を守り、読取り時に元へ復元します。更新・削除・期限切れ時には古い分割データも整理します。
- 定期的な権限確認と、操作停止後10秒の送信予約はDurable Objectのアラームで再開します。ブラウザーが閉じても予約を保持します。
- Cloudflareでの外部HTTPは`fetch`の呼出し元を固定し、転送は`manual`で追跡せず3xxを拒否します。NotionトークンやAIキーを転送先へ渡しません。
- Gmail SMTPは既存設定をサーバーのSecretへ登録します。登録済みメールの所有確認、パスワード、パスキー、CSRF、Origin検証は継続します。

## 移行

利用者が明示許可したGmail送信設定とNotionトークンを、専用WorkerのSecretとして登録しました。ソース・GitHub Pages・静的アセット・バンドルへは含めません。

稼働中のローカルアプリを停止して整合バックアップを保存し、ワークショップ・利用者設定・合計票と個人票・議論・マップ・AI用mdを専用ストレージへ移しました。内容ハッシュを照合し、62項目を含む内容の一致を確認しました。

移行機能は、短期Secretの`MIGRATION_TOKEN`を使い、空の移行先に対して1回だけ実行できます。移行中は公開側の通常操作とアラームを止めます。移行完了後はそのSecretを削除し、移行APIが404になることまで確認しました。

ローカルのログインセッションは持ち込みません。公開URLで改めてログインしてください。localhostで登録したパスキーは公開ホスト用に再登録が必要です。ローカルのバックアップは復旧用に保持し、Notionへ書くアプリを2か所で同時運用しません。

## 検証の範囲

全82件の自動テスト、分離したローカルWorkerでの永続保存・移行の1回制限・未認証拒否、公開Workerの起動とOTP設定有効を確認しました。公開側でGmail SMTP認証とNotionの実読取りも成功しています。公開URLで利用者が受信したOTPを使う最終ログインは、利用者による確認事項です。
